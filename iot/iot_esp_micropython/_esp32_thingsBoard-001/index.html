    Utilizando o ThingsBoard com ESP32 e MicroPython¶

    Você já montou um projeto com ESP32, mediu temperatura, umidade, corrente… e quando terminou percebeu que tudo o que tinha era um print() no terminal e alguns gráficos improvisados em planilha?

    Você não está sozinho.

    Problema: a maioria dos projetos com ESP32 e sensores morre no cabo USB. Sem uma boa plataforma de IoT, fica difícil:

    • Visualizar dados em tempo real de forma bonita;
    • Guardar histórico para análise;
    • Controlar o dispositivo remotamente;
    • Escalar de “um protótipo na bancada” para “dezenas ou centenas de dispositivos em campo”.

    Agitação: isso significa retrabalho, frustração e projetos que não passam da fase de testes. Cada nova prova de conceito exige um back-end diferente, dashboards novos, scripts artesanais… e, quando alguém pergunta “dá pra ver isso na nuvem?”, o projeto trava.

    Solução: combinar o ESP32 rodando MicroPython com o ThingsBoard, uma plataforma IoT open-source robusta, usada em contextos reais de automação, telemetria e SCADA de baixo custo. Neste guia, você vai do zero até: aimspress

    • Conectar seu ESP32 + MicroPython ao ThingsBoard via MQTT;
    • Enviar telemetria (ex.: temperatura, umidade);
    • Publicar atributos do dispositivo;
    • Receber comandos RPC para acionar, por exemplo, um LED ou relé;
    • Visualizar dados em dashboards profissionais, prontos para impressionar clientes, professores ou gestores.

    Tudo isso com código limpo, exemplos práticos e explicações detalhadas.

    Visão geral: ESP32, MicroPython e ThingsBoard trabalhando juntos¶

    Nesta seção, você vai entender a arquitetura básica da solução antes de escrever qualquer linha de código. A ideia é que você enxergue “o filme completo”: do sensor no ESP32 até o gráfico no navegador.

    O que é o ThingsBoard (e por que usar com ESP32)?¶

    O ThingsBoard é uma plataforma IoT open-source que oferece:

    • Coleta e armazenamento de dados de dispositivos;
    • Dashboards dinâmicos e responsivos;
    • Processamento de eventos, alarmes e regras;
    • Controle de dispositivos através de RPC;
    • Controle de usuários, tenants, perfis de dispositivos e muito mais. youtube

    Ele já possui exemplos oficiais para ESP32 e integrações prontas para telemetria, atributos e RPC via MQTT. thingsboard

    O que o MicroPython traz para o ESP32¶

    O MicroPython permite programar o ESP32 em Python, com:

    • API de hardware (machine, network, esp32, etc.) para GPIO, ADC, PWM, etc.;
    • Suporte oficial ao ESP32, com documentação e exemplos claros; docs.micropython
    • Facilidade para testar interativamente via REPL.

    Isso significa que:

    • Você escreve menos código do que em C/C++;
    • Itera mais rápido;
    • Aprende conceitos de IoT focando na lógica, não na linguagem.

    Arquitetura da solução¶

    Em alto nível, o fluxo é:

    1. ESP32 + MicroPython coleta dados de sensores (ex.: temperatura);
    2. O ESP32 conecta na Wi-Fi e abre uma sessão MQTT com o ThingsBoard;
    3. Os dados são enviados como telemetria usando o SDK MicroPython para ThingsBoard; github
    4. ThingsBoard armazena, processa e exibe em dashboards;
    5. Opcionalmente, o ThingsBoard envia comandos (RPC) para o ESP32, que reage em tempo real.

    Arquitetura típica

    • Protocolo: MQTT sobre TCP (com ou sem TLS)
    • Formato dos dados: JSON
    • Autenticação: token de acesso ou outro método definido no ThingsBoard
    • Topologia mínima: 1 ESP32 → 1 instância do ThingsBoard → 1 dashboard

    Pré-requisitos e cenário do exemplo¶

    Aqui você vê o que precisa ter instalado e qual será o projeto de exemplo que vamos construir juntos.

    O que você precisa ter em mãos¶

    • 1 placa ESP32 compatível com MicroPython;
    • Cabo USB para programação;
    • Acesso a uma rede Wi-Fi 2.4 GHz;
    • Acesso a uma instância do ThingsBoard:
    • Pode ser a instância demo (demo.thingsboard.io);
    • Ou uma instalação local/servidor configurada por você;
    • Firmware MicroPython gravado na placa ESP32; docs.micropython
    • Um ambiente para enviar scripts:
    • Thonny, Mu Editor, rshell, mpremote ou similar.

    Recomendação prática

    Se você está apenas testando, use o demo.thingsboard.io.
    Ele é ideal para protótipos e para aprender o fluxo completo sem precisar instalar nada no servidor.

    Projeto de exemplo: estação de temperatura IoT com LED remoto¶

    Ao final do tutorial, você terá:

    • Um ESP32 lendo um valor de “temperatura” (podemos simular no ADC ou com uma constante);
    • Enviando essa temperatura periodicamente para o ThingsBoard (telemetria);
    • Recebendo um comando RPC do ThingsBoard para ligar/desligar um LED (ou GPIO que poderia acionar um relé);
    • Um dashboard com:
    • Gráfico da temperatura ao longo do tempo;
    • Um botão para controlar o LED remotamente.

    Passo 1: conectando o ESP32 à Wi-Fi com MicroPython¶

    Nesta seção, você vai configurar a conexão Wi-Fi do ESP32 com MicroPython, base para qualquer projeto IoT.

    Código básico de conexão Wi-Fi¶

    Crie um arquivo wifi.py no seu ESP32 com o seguinte conteúdo:

    import network
import time

SSID = "SUA_REDE_WIFI"
PASSWORD = "SUA_SENHA_WIFI"

def conecta_wifi(ssid=SSID, password=PASSWORD, timeout=15):
    wlan = network.WLAN(network.STA_IF)
    if not wlan.active():
        wlan.active(True)

    if not wlan.isconnected():
        print("Conectando ao Wi-Fi...")
        wlan.connect(ssid, password)

        t0 = time.time()
        while not wlan.isconnected():
            if time.time() - t0 > timeout:
                raise RuntimeError("Falha ao conectar ao Wi-Fi")
            time.sleep(1)

    print("Conectado! IP:", wlan.ifconfig()[0])
    return wlan

    Boas práticas de segurança

    Evite commitar SSID e senha de Wi-Fi em repositórios públicos.
    Use arquivos .gitignore, variáveis de ambiente ou scripts de configuração separados quando for publicar seu código.

    Passo 2: criando o dispositivo no ThingsBoard¶

    Agora vamos criar o dispositivo lógico no ThingsBoard, que representa o seu ESP32 dentro da plataforma.

    Criando o device e obtendo o access token¶

    1. Acesse sua instância ThingsBoard (ex.: https://demo.thingsboard.io).
    2. Faça login (use uma conta de teste ou de desenvolvimento).
    3. No menu lateral, vá em Devices (Dispositivos).
    4. Clique em “+” → Add new device.
    5. Dê um nome amigável (ex.: ESP32-MicroPython-01).
    6. Salve.

    Depois:

    1. Clique no dispositivo criado.
    2. Vá em “Copy access token” (geralmente em Credentials).
    3. Guarde esse token, pois será usado no ESP32 para autenticar no ThingsBoard.

    Tokens de acesso

    O token é, na prática, a “senha” do seu dispositivo IoT.
    Não compartilhe esses valores em código público, prints, ou repositórios sem proteção.

    Passo 3: instalando o client MicroPython para ThingsBoard¶

    Nesta seção, você vai instalar o SDK MQTT para ThingsBoard em MicroPython, que torna o código muito mais simples e legível.

    Opções de cliente MicroPython para ThingsBoard¶

    Existem duas abordagens principais:

    1. SDK oficial MicroPython da ThingsBoard:
      Fornecido no repositório thingsboard-micropython-client-sdk, com suporte a:
    2. Telemetria,
    3. Atributos,
    4. RPC,
    5. Provisionamento,

    6. Conexões criptografadas (TLS). github

    7. Cliente ThingsBoard para MicroPython via PyPI:
      thingsboard-micropython é uma biblioteca baseada em umqtt.robust, oferecendo um client para a Device API do ThingsBoard. pypi

    Neste artigo, vamos considerar o uso do SDK MicroPython da ThingsBoard por ser mantido pela equipe da própria plataforma e suportar os principais recursos MQTT da Device API. github

    Instalando via mip (no ESP32)¶

    No REPL do MicroPython (via Thonny, mpremote etc.), rode:

    import mip
mip.install('github:thingsboard/thingsboard-micropython-client-sdk')

    Isso vai fazer o download do SDK diretamente para a placa, tornando-o disponível para importação.

    Sem mip disponível?

    Se não conseguir usar mip (por rede restrita ou firmware antigo),
    você pode: - Fazer download do repositório no seu PC; - Copiar a pasta do SDK para o ESP32 usando Thonny, rshell ou outra ferramenta.

    Passo 4: primeiro envio de telemetria (Hello ThingsBoard!)¶

    Agora começa a parte divertida: vamos enviar nosso primeiro dado de telemetria da placa para o dashboard.

    Estrutura básica do código (telemetria simples)¶

    Crie um arquivo main.py no ESP32 com o seguinte:

    import time
from wifi import conecta_wifi
from thingsboard_sdk.tb_device_mqtt import TBDeviceMqttClient

THINGSBOARD_HOST = "demo.thingsboard.io"  # ou IP/host da sua instância
ACCESS_TOKEN = "SEU_ACCESS_TOKEN_AQUI"    # copiado do ThingsBoard

def conecta_thingsboard():
    print("Conectando ao ThingsBoard...")
    client = TBDeviceMqttClient(THINGSBOARD_HOST, ACCESS_TOKEN)
    client.connect()
    print("Conectado ao ThingsBoard!")
    return client

def main():
    # 1. Conecta na Wi-Fi
    conecta_wifi()

    # 2. Conecta ao ThingsBoard
    client = conecta_thingsboard()

    # 3. Envia alguns valores de exemplo
    try:
        for i in range(10):
            temperatura = 25 + i * 0.1
            dados = {
                "temperature": temperatura,
                "enabled": True
            }
            print("Enviando telemetria:", dados)
            client.send_telemetry(dados)
            time.sleep(5)
    finally:
        print("Desconectando...")
        client.disconnect()

if __name__ == "__main__":
    main()

    Após salvar e rodar:

    1. No ThingsBoard, abra o dispositivo;
    2. Vá em Latest telemetry ou em um dashboard conectado a esse device;
    3. Confira se os dados de temperature começam a aparecer.

    Primeira validação rápida

    • Se você vê a temperatura mudando na aba Latest telemetry,
      o canal ESP32 → MQTT → ThingsBoard está funcionando.
    • O próximo passo é transformar isso em um gráfico bonito no dashboard.

    Passo 5: leitura de sensor (ADC) no ESP32 com MicroPython¶

    Nesta seção, vamos trocar o valor “fake” da temperatura por algo que vem do hardware – por exemplo, um sensor conectado em uma entrada analógica (ADC).

    Lendo um valor no ADC com MicroPython¶

    O MicroPython oferece a classe ADC para ler entradas analógicas no ESP32. docs.micropython Segue um exemplo simplificado:

    from machine import ADC, Pin

adc = ADC(Pin(34))         # Use um pino ADC válido da sua placa
adc.atten(ADC.ATTN_11DB)   # faixa de ~0-3.3V
adc.width(ADC.WIDTH_12BIT) # resolução 0-4095

def le_sensor():
    valor_bruto = adc.read()
    # Exemplo: converter para "temperatura" fictícia
    temperatura = 20 + (valor_bruto / 4095) * 10  # 20°C a 30°C
    return temperatura

    Agora integre isso ao seu main.py:

    import time
from wifi import conecta_wifi
from thingsboard_sdk.tb_device_mqtt import TBDeviceMqttClient
from machine import ADC, Pin

THINGSBOARD_HOST = "demo.thingsboard.io"
ACCESS_TOKEN = "SEU_ACCESS_TOKEN_AQUI"

adc = ADC(Pin(34))
adc.atten(ADC.ATTN_11DB)
adc.width(ADC.WIDTH_12BIT)

def le_temperatura():
    valor = adc.read()
    temperatura = 20 + (valor / 4095) * 10
    return round(temperatura, 2)

def conecta_thingsboard():
    print("Conectando ao ThingsBoard...")
    client = TBDeviceMqttClient(THINGSBOARD_HOST, ACCESS_TOKEN)
    client.connect()
    print("Conectado ao ThingsBoard!")
    return client

def main():
    conecta_wifi()
    client = conecta_thingsboard()

    try:
        while True:
            temp = le_temperatura()
            dados = {"temperature": temp}
            print("Telemetria:", dados)
            client.send_telemetry(dados)
            time.sleep(10)
    finally:
        client.disconnect()

if __name__ == "__main__":
    main()

    Substitua o ADC por um sensor real

    Se você tiver um sensor de temperatura (DHT22, DS18B20, etc.),
    basta trocar a função le_temperatura() pela leitura real do seu sensor
    e manter o restante do fluxo exatamente igual.

    Passo 6: controlando um LED via RPC (comando remoto)¶

    Aqui está a parte que impressiona: receber um comando do ThingsBoard para ligar/desligar um LED conectado ao ESP32.

    Configurando o LED no ESP32¶

    No ESP32, escolha um pino digital (por exemplo, GPIO 2):

    from machine import Pin

led = Pin(2, Pin.OUT)

def set_led_estado(ligado: bool):
    led.value(1 if ligado else 0)

    Assinando comandos RPC com o SDK MicroPython¶

    O TBDeviceMqttClient permite assinar RPC calls (server-side) do ThingsBoard. github Um fluxo básico:

    import time
from wifi import conecta_wifi
from thingsboard_sdk.tb_device_mqtt import TBDeviceMqttClient
from machine import Pin

THINGSBOARD_HOST = "demo.thingsboard.io"
ACCESS_TOKEN = "SEU_ACCESS_TOKEN_AQUI"

led = Pin(2, Pin.OUT)

def set_led_estado(ligado: bool):
    led.value(1 if ligado else 0)
    print("LED ligado" if ligado else "LED desligado")

def on_rpc_request(client, request_id, request_body):
    print("RPC recebido:", request_id, request_body)
    metodo = request_body.get("method")
    params = request_body.get("params")

    if metodo == "setLed":
        # 'params' pode ser True/False ou algo equivalente
        estado = bool(params)
        set_led_estado(estado)
        # Opcional: responder com um status
        client.send_rpc_reply(request_id, {"status": "ok", "led": estado})
    else:
        print("Método RPC desconhecido:", metodo)

def main():
    conecta_wifi()

    client = TBDeviceMqttClient(THINGSBOARD_HOST, ACCESS_TOKEN)

    # Registra o callback para RPC
    client.set_server_side_rpc_request_handler(on_rpc_request)

    client.connect()
    print("Conectado com suporte a RPC.")

    try:
        while True:
            # Mantém o loop rodando e processando mensagens MQTT
            client.check_msg()
            time.sleep(0.1)
    finally:
        client.disconnect()

if __name__ == "__main__":
    main()

    Criando o botão de controle no dashboard¶

    No ThingsBoard:

    1. Crie (ou edite) um dashboard associado ao seu device;
    2. Adicione um widget de RPC (ex.: “Switch control”);
    3. Configure para:
    4. RPC method: setLed (mesmo texto usado no código);
    5. Parameters: true/false conforme o estado do botão.

    Agora, quando você clicar no botão no dashboard:

    • O ThingsBoard envia um comando RPC setLed para o ESP32;
    • O ESP32 recebe no on_rpc_request;
    • O LED muda de estado em tempo real.

    Cenário prático

    Imagine esse LED ligado a um relé controlando uma lâmpada ou uma bomba d’água.
    Com poucas linhas de código, você sai do “protótipo isolado” para um atuador remoto controlado via nuvem.

    Passo 7: atributos do dispositivo – metadados e configurações¶

    Além de telemetria e RPC, o ThingsBoard permite trabalhar com atributos (device attributes), que são ideais para:

    • Guardar configurações (ex.: intervalo de envio, thresholds);
    • Registrar informações estáticas do device (ex.: localização, firmware).

    O SDK MicroPython também expõe APIs para isso. github

    Publicando atributos do lado do cliente¶

    Exemplo simples de envio de atributos:

    from wifi import conecta_wifi
from thingsboard_sdk.tb_device_mqtt import TBDeviceMqttClient

THINGSBOARD_HOST = "demo.thingsboard.io"
ACCESS_TOKEN = "SEU_ACCESS_TOKEN_AQUI"

def main():
    conecta_wifi()
    client = TBDeviceMqttClient(THINGSBOARD_HOST, ACCESS_TOKEN)
    client.connect()

    atributos = {
        "fw_version": "1.0.0",
        "modelo": "ESP32-MP-ThingBoard",
        "local": "Laboratório 1"
    }

    print("Enviando atributos:", atributos)
    client.send_attributes(atributos)

    client.disconnect()

if __name__ == "__main__":
    main()

    No ThingsBoard, você verá esses atributos no painel do dispositivo, em Attributes → Client attributes.

    Configurações dinâmicas com atributos compartilhados

    Você pode usar shared attributes para mandar configurações do servidor para o device
    (ex.: mudar o intervalo de envio de telemetria sem regravar o firmware).
    Basta assinar mudanças de atributos no SDK e reagir às atualizações no código.

    Erros comuns ao integrar ESP32 + ThingsBoard¶

    • Credenciais erradas:
    • Token de acesso copiado do dispositivo errado;
    • Host incorreto (demo.thingsboard.io vs. IP local).
    • Rede bloqueando MQTT:
    • Firewalls corporativos podem bloquear a porta 1883 (MQTT sem TLS);
    • Considere usar portas e configurações compatíveis com sua infraestrutura.
    • Loop principal sem check_msg():
    • Se você não chama check_msg() periodicamente, RPC e atualizações não chegam.
    • Watchdog “invisível”:
    • Loops bloqueantes sem sleep podem travar a placa ou impedir a manutenção da conexão MQTT.

    Boas práticas para projetos de verdade¶

    • Separar ambientes:
    • Tenha uma instância ThingsBoard para desenvolvimento e outra para produção.
    • Provisionamento em massa:
    • Explore os recursos de provisioning devices do ThingsBoard para escalar centenas de dispositivos sem configurar um a um. thingsboard
    • Segurança:
    • Considere usar MQTT com TLS e métodos de autenticação mais robustos para ambientes críticos. github
    • Organização do código:
    • Modularize em arquivos (wifi.py, sensors.py, thingsboard_client.py, main.py) para facilitar manutenção.

    Não subestime logs e monitoramento

    Sempre que possível, logue eventos-chave (conexão, reconexão, falhas de envio, comandos recebidos).
    Em campo, isso reduz drasticamente o tempo de diagnóstico quando algo “misteriosamente” para de funcionar.
