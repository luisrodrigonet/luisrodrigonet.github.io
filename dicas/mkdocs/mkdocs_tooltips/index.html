    Configuração e Uso de Tooltips no MkDocs

    📑 Introdução: Por Que Tooltips Importam¶

    Imagine um leitor consultando sua documentação técnica. Ele encontra um termo desconhecido, um acrônimo complexo ou uma sigla que não compreende. Sem uma explicação rápida e contextual, ele pode abandonar a página ou se sentir perdido. É aqui que os tooltips entram em cena como seus aliados silenciosos.

    Um tooltip é um pequeno elemento visual que aparece quando o usuário passa o mouse sobre um elemento específico — oferecendo informações complementares, explicações breves ou definições sem interromper o fluxo de leitura. No Material for MkDocs, os tooltips não são apenas funcionais; eles são visualmente elegantes, acessíveis e fáceis de implementar.

    O Que Você Aprenderá Neste Artigo

    Este guia mostrará como:

    • Entender o propósito e os benefícios dos tooltips
    • Configurar tooltips no seu projeto MkDocs
    • Implementar tooltips em links e outros elementos
    • Criar glossários automáticos para seu projeto
    • Evitar armadilhas comuns de implementação

    Antes de mergulhar na técnica, vamos entender o por quê. Os tooltips resolvem um dilema clássico da documentação: como fornecer informações detalhadas sem sobrecarregar a página com texto?

    Os Benefícios Práticos¶

    • Redução de Carga Cognitiva: Seus leitores não precisam saltar entre páginas ou rolar extensamente para entender termos específicos. A informação vem até eles.
    • Manutenção Centralizada: Ao usar um glossário compartilhado, você define uma abreviação ou termo uma única vez e ele fica disponível em todo o seu projeto automaticamente.
    • Melhor Experiência do Usuário: Tooltips bem-executados criam uma sensação de sofisticação e profissionalismo, elevando a percepção de qualidade da sua documentação.
    • Acessibilidade Aprimorada: Material for MkDocs implementa tooltips de forma acessível, respeitando as melhores práticas de inclusão digital.

    Dica: Use Tooltips Estrategicamente

    Não abuse de tooltips! Reserve-os para:

    • Termos técnicos importantes
    • Acrônimos que aparecem frequentemente
    • Conceitos que facilitam, mas não são essenciais

    Informações críticas devem estar visíveis no texto principal.

    🏗️ Configuração: Ativando Tooltips no MkDocs¶

    A beleza dos tooltips no Material for MkDocs é que a implementação é simples e direta. Tudo começa no arquivo mkdocs.yml, o coração de toda configuração do seu projeto.

    1️⃣ Ativar Extensões Markdown¶

    Abra seu arquivo mkdocs.yml e adicione as seguintes extensões Markdown:

    markdown_extensions:
  - abbr
  - attr_list
  - pymdownx.snippets

    O que cada extensão faz:

    • abbr: Permite definir abreviações e siglas que se transformarão em tooltips
    • attr_list: Possibilita adicionar atributos (como title) a elementos individuais
    • pymdownx.snippets: Permite importar conteúdo de arquivos externos, útil para glossários compartilhados

    2️⃣ Ativar Tooltips Melhorados¶

    Agora, ative os tooltips visuais do Material for MkDocs adicionando a seguinte configuração:

    theme:
  features:
    - content.tooltips

    Compatibilidade de Temas

    A feature content.tooltips é específica do Material for MkDocs. Se você usa outro tema, a funcionalidade pode não estar disponível.

    3️⃣ Exemplo Completo de Configuração¶

    Para referência, aqui está como uma seção do seu mkdocs.yml deve parecer após essas mudanças:

    site_name: Minha Documentação Técnica
theme:
  name: material
  features:
    - content.tooltips
    - content.code.copy

markdown_extensions:
  - abbr
  - attr_list
  - pymdownx.snippets
  - pymdownx.highlight:
      anchor_linenums: true
  - pymdownx.inlinehilite

    Pronto para o Próximo Passo

    Após fazer essas alterações, execute mkdocs serve para recarregar o projeto. Agora você está pronto para começar a implementar tooltips!

    🛠️ Implementação Prática: Adicionando Tooltips¶

    Existem várias formas de adicionar tooltips em MkDocs. Cada uma serve para um propósito diferente.

    🔖 Método 1: Tooltips em Links¶

    A forma mais simples de adicionar um tooltip é aproveitar a sintaxe nativa do Markdown para links. Adicione um título entre aspas após o URL:

    [Clique aqui](https://example.com "Este é meu tooltip!")

    Como funciona: Quando o usuário passa o mouse sobre o link "Clique aqui", um tooltip elegante aparece mostrando "Este é meu tooltip!"

    Visite a documentação oficial do MkDocs para aprender mais sobre o projeto.

    🔖 Método 2: Tooltips em Ícones e Elementos Específicos¶

    Para adicionar tooltips a elementos que não são links, como ícones ou blocos de código, use a extensão Attribute Lists. Ela permite adicionar o atributo title a praticamente qualquer elemento:

    :material-information-outline:{ title="Clique para mais informações" }

    Este código renderiza um ícone com um tooltip contextual. É perfeito para destacar dicas ou alertas sem quebrar o design.

    🔖 Método 3: Tooltips com Abreviações (Glossário Automático)¶

    Este é o método mais poderoso para projetos grandes. Você define uma abreviação uma vez e ela ganha um tooltip automaticamente em todo o seu projeto.

    1️⃣ Definindo Abreviações Localmente¶

    No seu arquivo Markdown, adicione as definições no final:

    # Meu Artigo Sobre Cloud Computing

A HTML é a linguagem base da web.

*[HTML]: Hyper Text Markup Language

    Agora, sempre que "HTML" aparecer no texto, um tooltip será exibido automaticamente com a definição "Hyper Text Markup Language".

    2️⃣ Criando um Glossário Compartilhado¶

    Para projetos maiores, é melhor manter um glossário centralizado. Crie um arquivo chamado glossary.md na pasta includes/ (fora de docs/):

    *[API]: Application Programming Interface
*[REST]: Representational State Transfer
*[JSON]: JavaScript Object Notation
*[YAML]: YAML Ain't Markup Language
*[CSS]: Cascading Style Sheets
*[HTTP]: HyperText Transfer Protocol
*[HTTPS]: HyperText Transfer Protocol Secure
*[DOM]: Document Object Model

    Estrutura de Pastas Recomendada

    projeto/
├── docs/
│   ├── index.md
│   ├── guia/
│   │   └── introducao.md
│   └── api/
│       └── endpoints.md
├── includes/
│   └── glossary.md  <- AQUI
└── mkdocs.yml

    Depois, adicione ao seu mkdocs.yml a configuração para importar este glossário automaticamente:

    markdown_extensions:
  - pymdownx.snippets:
      base_path:
        - includes

nav:
  - Início: index.md
  - Guias:
    - Introdução: guia/introducao.md

    E no início ou fim de cada arquivo Markdown que quer usar o glossário, adicione:

    --8< -- "glossary.md"

    Benefício da Abordagem Centralizada

    Ao usar um glossário centralizado, você pode:

    • Manter consistência de definições em todo o projeto
    • Atualizar uma definição uma única vez e ter efeito em todo lugar
    • Reutilizar o glossário em múltiplos projetos

    💻 Boas Práticas: Implementando Tooltips com Inteligência¶

    Ter o poder de adicionar tooltips não significa que você deva adicionar em tudo. Aqui estão as melhores práticas para usar tooltips de forma eficaz:

    ✅ Faça Isso¶

    Use tooltips para:

    • Defina termos técnicos e acrônimos que aparecem frequentemente
    • Explique conceitos que são úteis, mas tangenciais ao tópico principal
    • Forneça links para recursos relacionados em contexto
    • Clarificar abreviações que podem ser ambíguas

    ❌ Evite Isso¶

    Não use tooltips para:

    • Informação crítica que o usuário precisa ler (coloque no texto principal)
    • Explicações longas que precisam de vários parágrafos (use uma página separada)
    • Chamadas para ação importantes (deixe visível o tempo todo)
    • Instruções passo a passo (devem estar no fluxo principal)

    Cuidado com Dispositivos Móveis

    Lembre-se que em dispositivos móveis, não existe "passar o mouse". Considere usar abreviações com glossário, que funcionam universalmente, em vez de apenas tooltips em links.

    🚨 Solução de Problemas: O Que Fazer Se Algo Não Funcionar¶

    1️⃣ Tooltips não aparecem ao passar o mouse¶

    • Solução 1: Verifique se content.tooltips está ativado em theme.features
    • Solução 2: Certifique-se de que a extensão attr_list está incluída em markdown_extensions
    • Solução 3: Recarregue o navegador (limpe o cache)

    2️⃣ Abreviações não funcionam em todo o projeto¶

    Solução: Verifique se você está usando a sintaxe correta: 

    *[SIGLA]: Significado completo

    Não use **[SIGLA]** (com dois asteriscos) nem outras variações.

    3️⃣ Glossário centralizado não está sendo importado¶

    Solução: Confirme que:

    1. O arquivo glossary.md está na pasta includes/
    2. A pasta includes/ está registrada em watch no mkdocs.yml
    3. Você adicionou --8<-- "glossary.md" no arquivo Markdown

    Verificação Rápida

    watch:
  - includes
