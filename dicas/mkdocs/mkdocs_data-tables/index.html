    📅 Configuração e Uso de Data Tables no Material for MkDocs¶

    Você está criando documentação, mas suas tabelas parecem saídas dos anos 90. Linhas finas, sem estilo, dificilmente legíveis em mobile. Seus usuários reclamam que não conseguem encontrar informações rapidamente. E aquela tabela com 50 linhas? Esquece, ninguém vai scrollar até o final.

    A realidade é que tabelas bem estruturadas são ferramentas poderosas de comunicação. Elas transformam dados brutos em insight acionável. Mas apenas se forem feitas certo.

    A boa notícia é que o Material for MkDocs foi projetado especificamente para resolver isso. Com configuração minimalista e suporte nativo a tabelas profissionais, você consegue apresentar dados de forma clara, acessível e visualmente agradável. Não precisa saber HTML complexo. Não precisa de bibliotecas pesadas. Markdown puro + um pouco de magia do Material.

    E o melhor? Suas tabelas serão automaticamente responsivas, acessíveis e até interativas (sim, com ordenação clicável).

    Este artigo é seu mapa completo. Vamos desde a configuração básica até personalizações avançadas, passando por boas práticas de acessibilidade que garantem que 100% dos seus leitores consigam entender suas tabelas — deficientes visuais, usuários de teclado, everyone.

    1️⃣ Configuração Inicial: O Primeiro Passo¶

    Toda tabela começa com uma configuração. E a boa notícia? No Material for MkDocs, é trivial.

    🏗️ Habilitando Suporte a Tabelas¶

    Para que suas tabelas Markdown sejam renderizadas corretamente, você precisa adicionar uma simples extensão ao seu arquivo mkdocs.yml. Este arquivo é o "cérebro" do seu projeto de documentação — nele você configura tudo sobre como seu site funciona.

    Abra seu mkdocs.yml e localize a seção markdown_extensions. Se ela não existir, crie-a. Adicione o seguinte:

    Arquivo: mkdocs.yml

    markdown_extensions:
- tables

    Pronto. É literalmente isso. A extensão tables é o que permite que Markdown "entenda" tabelas e as converta em HTML elegante.

    Configuração Padrão

    Na maioria das vezes, a extensão tables já vem habilitada por padrão no Material for MkDocs. Se ainda assim suas tabelas não funcionarem, essa configuração explícita resolverá o problema. Considere isso como uma "segurança extra".

    🏗️ Por que essa configuração importa¶

    Sem essa extensão, quando você escreve uma tabela em Markdown, o Material for MkDocs simplesmente a ignora — o texto aparece como parágrafo comum. Com ela ativada, o parser Markdown reconhece a sintaxe e gera uma tabela HTML estruturada, semanticamente correta e estilizada.

    Estamos falando de acessibilidade automática: leitores de tela entendem a estrutura. Usuários em mobile conseguem scrollar horizontalmente. Mecanismos de busca indexam os dados. Tudo por uma única linha de configuração.

    2️⃣ Sintaxe Básica: Escrevendo sua Primeira Tabela¶

    Agora que a configuração está pronta, vamos criar tabelas. A sintaxe Markdown para tabelas é intuitiva e segue um padrão simples: barras verticais (|) separam colunas, hifens (-) definem o cabeçalho.

    🏗️ Estrutura Fundamental¶

    Toda tabela segue esta estrutura:

    Exemplo:

    | Coluna 1    | Coluna 2       |
| ----------- | -------------- |
| Dados 1     | Dados 2        |
| Dados 3     | Dados 4        |

    Quando renderizada, você verá:

    Coluna 1 Coluna 2
    Dados 1 Dados 2
    Dados 3 Dados 4

    Anatomia da tabela Markdown:

    1. Primeira linha: Cabeçalhos (aquilo que você quer que apareça em negrito e centrado)
    2. Segunda linha: Divisor — mínimo 3 hifens por coluna, separados por |
    3. Linhas seguintes: Dados da tabela

    Erros Comuns

    • Esquecer a segunda linha (divisor com hifens) — sem ela, Markdown não reconhece como tabela
    • Usar número diferente de | em cada linha — mantenha consistência
    • Deixar espaços faltando ou extras pode causar formatação estranha

    🏗️ Exemplo Prático: Tabela de Endpoints de API¶

    Imagine que você está documentando uma API REST. Você precisa mostrar quais métodos HTTP existem, o que cada um faz, e que dados retorna. Uma tabela é perfeita para isso.

    Exemplo:

    | Método | Endpoint       | Descrição                    |
| ------ | -------------- | ---------------------------- |
| GET    | /usuarios      | Retorna lista de usuários    |
| POST   | /usuarios      | Cria novo usuário            |
| PUT    | /usuarios/{id} | Atualiza usuário existente   |
| DELETE | /usuarios/{id} | Remove usuário do sistema    |

    🚀 Resultado esperado

    Método Endpoint Descrição
    GET /usuarios Retorna lista de usuários
    POST /usuarios Cria novo usuário
    PUT /usuarios/{id} Atualiza usuário existente
    DELETE /usuarios/{id} Remove usuário do sistema

    Viu como fica profissional? Dados organizados, fáceis de scannear, claros. É por isso que tabelas são tão poderosas em documentação.

    3️⃣ Alinhamento de Colunas: Controle Visual Preciso¶

    Nem sempre você quer que todo texto fique alinhado à esquerda. Às vezes um número faz mais sentido alinhado à direita. Um título, centralizado. O Material for MkDocs permite isso com uma sintaxe super simples.

    🏗️ Os Três Alinhamentos¶

    O alinhamento é controlado usando dois-pontos (:) na linha divisora:

    Sintaxe Alinhamento Uso Ideal
    :--- Esquerda Texto, descrições
    :---: Centro Títulos, status
    ---: Direita Números, valores

    📝 Exemplos Práticos¶

    Tabela de Preços (números alinhados à direita):

    | Produto      | Preço  | Estoque |
| :----------- | ------: | ------: |
| Notebook     | R$ 3.500 | 12     |
| Mouse        | R$ 85    | 45     |
| Teclado      | R$ 250   | 8      |

    🚀 Resultado esperado

    Produto Preço Estoque
    Notebook R$ 3.500 12
    Mouse R$ 85 45
    Teclado R$ 250 8

    Viu a diferença? Com números alinhados à direita, fica muito mais fácil comparar valores. Seu olho naturalmente os agrupa.

    Tabela de Funcionalidades (status centralizado):

    | Feature              | Status     | Lançamento |
| :------------------- | :--------: | ---------- |
| Autenticação OAuth   | ✅ Pronto  | v2.0       |
| Integração Stripe    | 🔄 Teste  | v2.1       |
| Exportar em PDF      | ⏳ Planejado | v2.2      |

    🚀 Resultado esperado

    Feature Status Lançamento
    Autenticação OAuth ✅ Pronto v2.0
    Integração Stripe 🔄 Teste v2.1
    Exportar em PDF ⏳ Planejado v2.2

    Status centralizado fica mais visível, certo? Seu documento fica mais legível e profissional.

    Emojis e Ícones

    Material for MkDocs suporta emojis nativamente, e também ícones Material Design. Use-os para adicionar clareza visual: ✅ para sucesso, ❌ para erro, ⚠️ para aviso. Seus usuários vão apreciar a clareza.

    4️⃣ Conteúdo Rico: Tabelas com Markdown Avançado¶

    Aqui está um segredo que muitos não conhecem: você pode usar Markdown dentro de tabelas. Código inline, negrito, itálico, links — tudo funciona.

    🏗️ Exemplo: Tabela com Formatting

    Código :

    | Comando | Descrição | Exemplo |
| :------ | :-------- | :------ |
| `git add` | Adiciona arquivo ao staging | `git add .` |
| `git commit` | Cria um commit | `git commit -m "fix: bug"` |
| `git push` | Envia commits remotamente | `git push origin main` |

    🚀 Resultado esperado

    Comando Descrição Exemplo
    git add Adiciona arquivo ao staging git add .
    git commit Cria um commit git commit -m "fix: bug"
    git push Envia commits remotamente git push origin main

    Perceba como o código aparece em fonte monoespacada dentro da tabela. Perfeito para documentação técnica.

    🏗️ Exemplo: Tabela com Markdown Complexo

    Código :

    | Nível | Descrição | Exemplo |
| :--- | :-------- | :------ |
| **Iniciante** | Sem experiência prévia | Primeira vez aprendendo |
| *Intermediário* | Conhecimento sólido | Desenvolvendo projetos reais |
| ***Avançado*** | Expertise completa | Mentorando outros |

    🚀 Resultado esperado

    Nível Descrição Exemplo
    Iniciante Sem experiência prévia Primeira vez aprendendo
    Intermediário Conhecimento sólido Desenvolvendo projetos reais
    Avançado Expertise completa Mentorando outros

    A moral da história? Suas tabelas não precisam ser chatas. Use toda a riqueza do Markdown para comunicar melhor.

    5️⃣ Tabelas Ordenáveis: Interatividade Nativa¶

    Aqui está onde o Material for MkDocs realmente brilha. Com uma configuração minimalista, você pode fazer tabelas clicáveis e ordenáveis. Seus usuários podem ordenar por qualquer coluna.

    🏗️ Configurando Tabelas Ordenáveis¶

    Você precisa adicionar o JavaScript Tablesort. Crie (ou edite) o arquivo docs/overrides/main.html:

    Arquivo : docs/overrides/main.html 

    {% extends "base.html" %}

{% block libs %}
{{ super() }}
<script src="https://unpkg.com/tablesort@5.3.0/dist/tablesort.min.js"></script>
<script>
    document.addEventListener('DOMContentLoaded', function() {
    const tables = document.querySelectorAll("article table:not([class])");
    tables.forEach(table => new Tablesort(table));
    });
</script>
{% endblock %}

    E configure seu mkdocs.yml:

    Arquivo : mkdocs.yml 

    theme:
name: material
custom_dir: docs/overrides

    🏗️ Como Funciona¶

    Uma vez ativado, cada coluna se torna clicável. O usuário clica no cabeçalho e:

    • Primeira vez: ordena crescente
    • Segunda vez: ordena decrescente
    • Terceira vez: volta à ordem original

    É transparente, intuitivo, poderoso.

    Caso de Uso Real

    Imagine uma tabela de competidores com preços, features, ratings. Sem ordenação, o usuário precisa ler tudo. Com Tablesort, ele clica em "Preço" e vê do mais barato ao mais caro em segundos. Isso é diferencial de UX.

    🏗️ Exemplo: Tabela de Produtos com Ordenação¶

    Código : 

    | Produto | Preço (R$) | Rating | Disponível |
| :------ | ---------: | -----: | :--------: |
| Notebook Dell | 2.500 | 4.8 | ✅ |
| Notebook ASUS | 3.200 | 4.9 | ✅ |
| Notebook HP | 2.800 | 4.6 | ❌ |
| Notebook Lenovo | 2.200 | 4.7 | ✅ |

    🚀 Resultado esperado

    Produto Preço (R$) Rating Disponível
    Notebook Dell 2.500 4.8 ✅
    Notebook ASUS 3.200 4.9 ✅
    Notebook HP 2.800 4.6 ❌
    Notebook Lenovo 2.200 4.7 ✅

    Com essa configuração, o usuário pode clicar em "Preço" e ver do mais caro ao mais barato. Clica de novo, mais barato ao mais caro. Não é demais?

    Limitação Importante

    Tablesort funciona melhor com dados simples (texto, números, datas). Se sua tabela tem conteúdo HTML complexo, a ordenação pode não funcionar perfeitamente. Para esses casos, considere uma solução JavaScript mais robusta.

    6️⃣ Boas Práticas de Acessibilidade: Tabelas para Todos¶

    Aqui está a parte crítica que muitos ignoram: acessibilidade não é opcional, é obrigação. Pessoas cegas usam leitores de tela. Pessoas daltônicas precisam de texto claro, não apenas cores. Pessoas com dificuldade de motricidade precisam navegar com teclado.

    Tabelas mal estruturadas são barreiras para essas pessoas. Vamos evitar isso.

    🎯 Princípio 1: Headers Descritivos¶

    Seus cabeçalhos precisam ser ultra-claros. Não use abreviações misteriosas. "Dt. Ent. Esperado" é confuso. "Data de Entrega Esperada" é claro.

    Ruim: ❌

    | Prod. | Qtd. | Preço Un. | Total |

    Melhor: ✅

    | Produto | Quantidade | Preço Unitário (R$) | Total (R$) |

    Essa mudança simples faz enorme diferença para usuários de leitores de tela.

    🎯 Princípio 2: Estrutura Simples¶

    Evite tabelas complexas com múltiplas linhas de cabeçalho, células mescladas, ou layouts "criativos". Mantenha uma estrutura tabular pura:

    • Uma linha de cabeçalho
    • Várias linhas de dados
    • Sem células mescladas

    Se sua tabela precisa disso, provavelmente precisa ser dividida em tabelas menores ou reformatada.

    Evite: ❌

    | Região | Q1 | | | Q2 | | | |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| | Jan | Fev | Mar | Abr | Mai | Jun | |

    Melhor: ✅

    | Região | Janeiro | Fevereiro | Março |
| :--- | ---: | ---: | ---: |
| Centro | 1.200 | 1.450 | 1.680 |
| Sul | 890 | 920 | 1.100 |

    Duas tabelas simples (uma por trimestre) é melhor que uma tabela complexa. Seus usuários vão agradecer.

    🎯 Princípio 3: Contexto e Descrição¶

    Se sua tabela não é auto-explicativa, adicione um parágrafo introdutório ou uma legenda. Sempre indique por que a tabela existe.

    Exemplo completo :

    ## Histórico de Vendas por Região

A tabela abaixo mostra o desempenho de vendas em cada região durante 
o primeiro trimestre de 2025. Os valores estão em reais brasileiros (R$) 
e incluem impostos.

| Região | Janeiro | Fevereiro | Março |
| :--- | ---: | ---: | ---: |
| Centro | 1.200 | 1.450 | 1.680 |
| Sul | 890 | 920 | 1.100 |

    Esse contexto é crucial para leitores de tela e para qualquer pessoa que não entenda imediatamente o propósito da tabela.

    Legendas para Tabelas

    Se sua tabela contém abreviações ou símbolos especiais, adicione uma legenda embaixo:

    Símbolos: ✅ = Ativo | ❌ = Inativo | ⏳ = Pendente

    🎯 Princípio 4: Dados Numéricos Alinhados à Direita¶

    Isso facilita comparação e leitura:

    Exemplo :

    | Item | Quantidade | Preço Unitário |
| :--- | ---: | ---: |
| Maçã | 10 | 2,50 |
| Banana | 15 | 1,20 |
| Laranja | 8 | 3,00 |

    🚀 Resultado esperado

    Item Quantidade Preço Unitário
    Maçã 10 2,50
    Banana 15 1,20
    Laranja 8 3,00

    Seu olho naturalmente agrupa números. Aproveite isso.

    8️⃣ Otimização para Mobile e Responsividade¶

    Material for MkDocs trata responsividade para você. Mas há algumas coisas que você pode fazer para melhorar a experiência mobile:

    🔖 Tabelas Largas em Mobile¶

    Se sua tabela tem muitas colunas, em mobile ficará "apertada". Material for MkDocs permite scroll horizontal automático. Você não precisa fazer nada — acontece naturalmente.

    Mas você pode ajudar seus usuários mobile de duas formas:

    1. Mantenha tabelas concisas

      • Não adicione colunas "só porque pode".
      • Cada coluna deve ter propósito claro.

    2. Considere ordem de importância

      • Coloque as informações mais importantes nas primeiras colunas (esquerda).
      • Em telas pequenas, o usuário scrollará para os lados — pelo menos as colunas críticas estarão visíveis.

    🔖 Exemplo: Tabela Otimizada para Mobile¶

    Exemplo :

    | Produto | Preço | Avaliação | Estoque |
| :------ | ----: | :-------: | :-----: |
| Notebook | R$ 3.500 | ⭐⭐⭐⭐⭐ | Sim |
| Mouse | R$ 85 | ⭐⭐⭐⭐ | Sim |

    🚀 Resultado esperado

    Produto Preço Avaliação Estoque
    Notebook R$ 3.500 ⭐⭐⭐⭐⭐ Sim
    Mouse R$ 85 ⭐⭐⭐⭐ Sim

    Simples, clara, com informações por ordem de importância. Perfeita para desktop e mobile.

    Evite Tabelas Ultra-Largas

    Se você precisa de 8+ colunas, considere: - Dividir em tabelas menores - Usar abas (tabs) para diferentes contextos - Oferecer versão resumida com link para detalhes

    9️⃣ Erros Comuns e Como Evitá-los¶

    Vamos ser honestos: tabelas Markdown são simples, mas alguns erros são super comuns.

    🚨 Erro 1: Inconsistência de Barras Verticais¶

    Codigo Errado :

    | Coluna 1 | Coluna 
| -------- | ---------
| Dado 1 | Dado 2

    Isso não renderiza como tabela. Cada linha precisa começar e terminar com |.

    ✅ Correto:

    Códgo Correto

    | Coluna 1 | Coluna 2 |
| -------- | --------- |
| Dado 1 | Dado 2 |

    🚨 Erro 2: Divisor com Poucos Hífens¶

    Codigo Errado :

    | Coluna Muito Grande | Coluna 2 |
| - | -- |
| Dado | Dado |

    Material for MkDocs é perdoador, mas o padrão é usar mínimo 3 hifens: ---. Use ------- para colunas largas.

    ✅ Melhor:

    Códgo Correto

    | Coluna Muito Grande | Coluna 2 |
| ----------- | --- |
| Dado | Dado |

    🚨 Erro 3: Não Indicar Contexto¶

    Tabela sem introdução é confusa. Sempre adicione um parágrafo explicativo ou heading.

    Codigo :

    ### Comparação de Planos

A tabela abaixo mostra qual plano é ideal para cada tipo de usuário:

| Plano | Ideal Para |
| :--- | :--- |
| Gratuito | Testes e prototipagem |
| Pro | Startups e pequenas equipes |
| Enterprise | Grandes corporações |

    Sem contexto, o usuário fica perdido. Com contexto, fica cristalino.

    🚨 Erro 4: Dados Inconsistentes¶

    Não misture unidades, formatos, ou magnitudes na mesma coluna:

    Evite :

    | Metric | Valor |
| :--- | ---: |
| Usuários | 1.500 |
| Logins | 45.000 |
| Receita | R$ 234 mil |
| Churn | 2,3% |

    Sem padrão. Uma coluna tem números, outra tem moeda, outra tem percentual.

    Melhor :

    | Métrica | Valor | Unidade |
| :--- | ---: | :--- |
| Usuários Ativos | 1.500 | Contagem |
| Logins Este Mês | 45.000 | Contagem |
| Receita | 234.000 | BRL |
| Taxa de Churn | 2,3 | % |

    Agora está claro. Cada coluna tem tipo e unidade definidos no cabeçalho.

    🔟 Checklist Final: Garantindo Tabelas Excelentes¶

    Antes de publicar qualquer tabela, passe por esse checklist:

    Qualidade de Tabelas

    • Tabela tem contexto introdutório (heading ou parágrafo)?
    • Headers são descritivos e não contêm abreviações obscuras?
    • Todas as linhas têm o mesmo número de colunas?
    • Dados numéricos estão alinhados à direita?
    • Tabela é simples o suficiente (máx 6-7 colunas)?
    • Sem células mescladas ou estrutura complexa?
    • Unidades estão claras (R$, %, km/h, etc)?
    • Tabela foi testada em mobile (horizontalmente legível)?
    • Emojis ou ícones melhoram clareza?
    • Há legenda se necessário?

    Se você marcou todas as caixas, sua tabela é profissional.
