    🖼️ Configuração e Uso de Images em MkDocs¶

    Você já parou para pensar no impacto que uma imagem bem posicionada tem na experiência do leitor? Enquanto milhares de palavras podem descrever um fluxo de trabalho complexo, uma screenshot estratégica comunica instantaneamente. É aqui que reside o verdadeiro potencial da documentação visual.

    Porém, há um problema silencioso que afeta muitos documentadores iniciantes: adicionar imagens sem estrutura adequada. Quando as imagens não são otimizadas, organizadas ou acessíveis, sua documentação sofre em três frentes críticas:

    1. Performance: Imagens pesadas deixam seu site mais lento
    2. Acessibilidade: Usuários com deficiência visual ficam perdidos
    3. Manutenção: Pastas desorganizadas viram pesadelos no futuro

    Neste guia, você aprenderá não apenas a inserir imagens, mas a dominar as técnicas profissionais que separam a documentação amadora da documentação de classe mundial. Descobriremos como o Material for MkDocs oferece recursos poderosos para transformar sua documentação visual em uma experiência imersiva e acessível.

    Ao final deste artigo, você será capaz de:

    • Inserir imagens locais e remotas de forma eficiente
    • Aplicar atributos avançados para controlar dimensões e comportamento
    • Implementar lazy-loading para melhorar o desempenho
    • Criar captions elegantes e acessíveis
    • Otimizar a visualização em modo claro e escuro
    • Organizar estruturas de diretórios de imagens profissionais

    Por que dominar imagens?

    • A inserção correta de imagens melhora a compreensão em até 65% e aumenta o tempo de permanência do leitor no site.
    • Em documentação técnica, imagens bem organizadas reduzem a curva de aprendizado significativamente.

    1️⃣ Estrutura de Pastas: O Alicerce da Organização¶

    Antes de inserir uma única imagem, você precisa entender a arquitetura de seu projeto. A organização de pastas é fundamental para manter sua documentação profissional e escalável.

    A melhor prática é centralizar suas imagens em uma pasta dedicada:

    Pasta : static/img

    seu-projeto/
├── mkdocs.yml
├── docs/
│   ├── index.md
│   ├── guia-rapido.md
│   ├── faq.md
│   └── static/
│       ├── img/
│       │   ├── logo.png
│       │   ├── screenshots/
│       │   │   ├── interface-dashboard.png
│       │   │   └── fluxo-usuario.png
│       │   ├── diagramas/
│       │   │   └── arquitetura-sistema.svg
│       │   └── icones/
│       │       └── check.svg
│       └── stylesheets/
│           └── custom.css

    Dica de Ouro

    Crie subpastas temáticas dentro de img/ (como screenshots/, diagramas/, icones/). Isso facilita a localização quando seu projeto crescer para centenas de imagens.

    • Use subpastas por seção: Mantenha imagens próximas ao conteúdo que ilustram
    • Nomeie descritivamente: configuracao-database.png é melhor que img1.png
    • Agrupe por tipo: Separar screenshots de ícones facilita manutenção
    • Use SVG para ícones: Ícones em SVG são escaláveis e ocupam menos espaço
    • Comprima PNG/JPG: Use ferramentas como TinyPNG para reduzir tamanho

    Por Que Esta Estrutura?

    Esta organização oferece três vantagens decisivas:

    • Escalabilidade: Conforme seu projeto cresce, encontrar uma imagem específica é trivial
    • Reutilização: Imagens compartilhadas ficam centralizadas e fáceis de manter
    • Deploy: Facilita scripts de otimização automatizada

    2️⃣ Configuração Inicial: Ativando os Recursos¶

    Antes de começar a trabalhar com imagens, você precisa configurar as extensões corretas no arquivo mkdocs.yml. Estas extensões adicionam funcionalidades essenciais ao Markdown padrão.

    Abra seu arquivo mkdocs.yml e adicione as seguintes extensões:

    Arquivo : mkdocs.yml

    markdown_extensions:
- attr_list       # Permite adicionar atributos HTML a elementos Markdown
- md_in_html      # Habilita Markdown dentro de tags HTML
- pymdownx.blocks.caption  # Suporte para captions (legendas)
    O que cada extensão faz?

    • attr_list:

      • Transforma atributos simples em propriedades HTML.
      • Permite usar sintaxe como { width="300" align=left } para controlar imagens.

    • md_in_html:

      • Permite que você misture Markdown puro com HTML quando necessário de controle fino.

    • pymdownx.blocks.caption:

      • Adiciona suporte nativo para legendas de forma elegante e semântica.

    Se você deseja adicionar funcionalidade de zoom ao clicar nas imagens, o plugin glightbox é a escolha ideal. Ele integra-se perfeitamente com Material for MkDocs.

    Instale o plugin:

    Comando :

    pip install mkdocs-glightbox

    Adicione ao mkdocs.yml:

    Arquivo : mkdocs.yml

    plugins:
- glightbox

    Importante

    O plugin glightbox é opcional, mas altamente recomendado para melhorar a experiência do usuário com imagens de alta resolução.

    3️⃣ Inserindo Imagens: Sintaxe Básica¶

    🔖 Sintaxe Padrão do Markdown¶

    A forma mais simples de inserir uma imagem é usar a sintaxe padrão do Markdown:

    Inserindo uma imagem

    ![Texto alternativo](caminho/para/imagem.png)

    Cada componente é essencial:

    Componente Descrição Exemplo
    ! Identificador de imagem (não é um link) !
    [Texto] Texto alternativo (importante para acessibilidade) [Configuração do banco de dados]
    (caminho) Caminho relativo ou URL absoluta ../images/config-db.png

    🔖 Diferenças: Imagens Locais vs. Remotas¶

    Imagem Local

    ![Meu screenshot](images/screenshot.png)

    Imagem Remota (URL):

    ![Logotipo do projeto](https://exemplo.com/logo.png)

    Quando usar cada uma?

    Imagens locais são mais rápidas, confiáveis e funcionam offline. Use quando possível.

    Imagens remotas são úteis para logotipos de terceiros ou conteúdo que muda frequentemente.

    4️⃣ Atributos Avançados de Imagens¶

    🔖 Dimensionamento: Controlando Largura e Altura¶

    O Markdown puro não suporta redimensionamento, mas as extensões permitem adicionar atributos HTML:

    Imagem dimensionada:

    ![Imagem pequena](images/diagrama.png){ width="300" }

    Resultados de diferentes configurações:

    Sintaxe Resultado
    { width="300" } Largura 300px, altura ajustada automaticamente
    { width="50%" } Ocupa 50% da largura do container
    { width="400" height="300" } Dimensões exatas (cuidado com distorção)
    { style="max-width: 200px" } Responsivo até 200px

    🏗️ Exemplo:

    Imagem dimensionada:

    ![Pagina de Abertura do Site](/static/img/mkdocs-dicas/mkdocs_001.png){ style="max-width: 500px" }

    🚀 Resultado esperado

    Dica Importante

    Especifique apenas largura OU altura, nunca ambas simultaneamente, a menos que a proporção original seja mantida. Caso contrário, a imagem ficará distorcida.

    🔖 Alinhamento de Imagens¶

    Alinhe imagens ao texto usando o atributo align:

    🚀 Alinhando à esquerda

    Alinhamento à esquerda:

    ![Imagem alinhada](images/foto.png){ align=left }

Este texto fluirá ao lado direito da imagem. A imagem ocupará espaço vertical conforme necessário.

    Resutado :

    Este texto fluirá ao lado direito da imagem. A imagem ocupará espaço vertical conforme necessário.

    🚀 Alinhando à Direita

    Alinhamento à Direita:

    ![Imagem alinhada](images/foto.png){ align=right }

Este texto fluirá ao lado esquerdo da imagem...

    Resutado :

    Este texto fluirá ao lado direito da imagem. A imagem ocupará espaço vertical conforme necessário.

    Comportamento Responsivo

    Em telas pequenas (mobile), as imagens se expandem automaticamente para toda a largura, e o texto flui abaixo. Isto garante legibilidade em qualquer dispositivo.

    🔖 Lazy Loading: Otimização de Desempenho¶

    O lazy loading carrega imagens apenas quando o usuário as visualiza, economizando banda:

    Código :

    ![Imagem com lazy loading](images/diagrama-grande.png){ loading=lazy }

    Quando usar lazy loading?

    ✓ Imagens grandes (>500KB)

    ✓ Muitas imagens na mesma página

    ✓ Documentação com grandes galerias

    ✗ Imagens visíveis na primeira tela

    5️⃣ Adicionando Captions (Legendas)¶

    Legendas transformam imagens simples em figuras semânticas, melhorando a apresentação:

    🔖 Método 1: Usando o Bloco Caption (Recomendado)¶

    Código 📋

    ![Pagina de Abertura do Site](/static/img/mkdocs-dicas/mkdocs_001.png){ style="max-width: 500px"}

/// caption
Página principal do site.
///

    Resultado esperado 🚀

    Resultado

    A imagem aparece com uma legenda elegante abaixo dela, em formatação menor e em cor mais suave.

    🔖 Método 2: Usando HTML Semântico¶

    Para mais controle, use as tags HTML <figure> e <figcaption>:

    Código 📋

    <figure markdown="span">
![Pagina de Abertura do Site](/static/img/mkdocs-dicas/mkdocs_001.png){ style="max-width: 500px"}
<figcaption>Página principal do site.</figcaption>
</figure>

    Resultado esperado 🚀

    Diferença de Sintaxes

    O bloco /// caption é mais limpo para Markdown puro.

    A tag HTML <figure> oferece maior compatibilidade com leitores de tela e motores de busca.

    8️⃣ Otimização: Desempenho e Acessibilidade¶

    🔖 Redimensionamento de Imagens¶

    Imagens grandes consomem banda. Sempre otimize:

    Ferramenta Propósito Resultado
    TinyPNG Comprimir PNG/JPG Redução de 50-80%
    ImageMagick Converter formatos Mudança de PNG para WebP
    ImageOptim (Mac) Otimização automática Remoção de metadados desnecessários
    GIMP Redimensionamento manual Controle total de dimensões

    Dica de Desempenho

    Use WebP para imagens fotográficas. Oferece qualidade superior em tamanho 25-35% menor que JPEG.

    9️⃣ Solução de Problemas Comuns¶

    🚨 Problema: Imagens Não Aparecem¶

    Causas possíveis:

    1. Caminho incorreto 

      ❌ ![img](./images/foto.png)     # Caminho absoluto problemático
✅ ![img](images/foto.png)       # Caminho relativo correto

    2. Arquivo não existe

      • Verifique se o arquivo realmente existe no diretório
      • Confirme a extensão (PNG, png, Png são diferentes em Linux)

    3. Estrutura de pastas errada

      • Imagens devem estar em pasta dentro de docs/
      • Nunca fora do diretório docs_dir

    Atenção

    O MkDocs copia apenas arquivos identificados como Markdown. Certifique-se que imagens estão em subpastas reconhecidas ou configure exclude_docs apropriadamente.

    Solução:

    Causa: Especificar ambas largura e altura com proporção diferente da original.
