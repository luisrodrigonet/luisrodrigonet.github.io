    Como usar Duck DNS no Debian Linux 13

    Introdução: acessando seu servidor de qualquer lugar¶

    Imagine a cena: você montou com todo carinho um servidor Debian 13 em casa — com SSH, talvez um Nextcloud, ou até um servidor de jogos — e, na primeira viagem, precisa acessar tudo remotamente. Quando tenta se conectar, o IP da sua casa mudou, e de repente aquele acesso “simples” vira uma caça ao tesouro.

    Este guia mostra, passo a passo, como usar o Duck DNS no Debian Linux 13 para ter um endereço fixo, mesmo com IP dinâmico do provedor, usando as mesmas práticas recomendadas em documentação oficial e tutoriais consolidados.

    Problema: IP dinâmico e frustração no acesso remoto¶

    A maioria dos provedores residenciais entrega um IP dinâmico ao roteador, que muda de tempos em tempos sem aviso. Sempre que isso acontece, qualquer acesso remoto que dependa do IP “quebra”.

    Na prática, isso significa:

    • Ter que descobrir o novo IP manualmente.
    • Atualizar configurações de clientes SSH, aplicativos de acesso remoto, VPNs, etc.
    • Interromper serviços que deveriam ser “sempre disponíveis” para você e sua equipe.

    Para quem administra servidores, mesmo que “de hobby”, isso é improdutivo, pouco profissional e inseguro (muita gente acaba usando serviços de acesso remoto duvidosos só para “facilitar”).

    Agora imagine que você:

    • Precisa pegar um arquivo importante que está no seu servidor de arquivos em casa.
    • Vai dar suporte remoto a um familiar usando um serviço que roda no seu Debian.
    • Depende de um túnel SSH para automatizar backups entre casa e escritório.

    Se o IP mudou e você não tem um nome de host estável, tudo isso para. E o pior: normalmente você descobre na pior hora possível, quando está longe, sem acesso ao roteador e sem como “ver” o novo IP público.

    É aqui que entra o DNS dinâmico (DDNS): um serviço que atualiza automaticamente o DNS sempre que o seu IP muda, mantendo um nome estável apontando para sua casa.

    Duck DNS + Debian 13¶

    Duck DNS é um serviço de DNS dinâmico gratuito, hospedado na AWS, que oferece domínios do tipo seudominio.duckdns.org e uma API simples para atualizar o IP por script.

    A própria documentação oficial mostra como integrar o serviço com scripts em Linux usando curl e cron, que é exatamente o que será feito (e melhorado) neste guia para Debian 13.

    Em alto nível, o que você vai montar:

    1. Criar um subdomínio gratuito no Duck DNS.
    2. Pegar o token de autenticação da sua conta.
    3. Configurar um script no Debian 13 que chama a API do Duck DNS.
    4. Agendar esse script com cron ou com systemd timers.
    5. Testar e usar esse endereço para acessar seus serviços (SSH, HTTP, etc.).

    O que você terá ao final

    Ao terminar o tutorial, você terá um hostname fixo (ex.: meu-server.duckdns.org) que sempre aponta para o IP público atual da sua conexão, atualizado automaticamente a cada poucos minutos.

    Pré-requisitos no Debian 13¶

    Antes de começar, garanta que você tem:

    • Uma máquina com Debian Linux 13 já instalada (servidor ou desktop).
    • Acesso de terminal com privilégios sudo.
    • Acesso à internet a partir desse Debian.
    • Possibilidade de abrir portas no seu roteador (para usar SSH, HTTP etc.).
    • Um navegador para criar a conta no Duck DNS.

    No Debian, usaremos:

    • curl: para chamar a API do Duck DNS.
    • cron ou systemd: para agendar as atualizações de IP.

    Passo 1: criar conta e domínio no Duck DNS¶

    O primeiro passo é criar sua identidade “fixa” na internet usando o Duck DNS.

    1.1 Criar conta¶

    1. Acesse o site oficial: https://www.duckdns.org.
    2. Faça login usando uma das opções suportadas (por exemplo, GitHub ou Google).
    3. Após o login, você verá a tela principal com:
      • Seu endereço de e-mail.
      • Seu token de autenticação (um UUID).
      • A área para criar domínios.

    Duck DNS é gratuito e foi criado justamente para oferecer DDNS simples, sem necessidade de pagamento nem renovações chatas de conta.

    Escolha um nome fácil de memorizar

    Pense em algo curto e descritivo, como casa-rodrigo, lab-debian ou homelab13. Esse será o nome que você usará em aplicativos, scripts e bookmarks.

    1.2 Criar o subdomínio¶

    1. Na tela principal do Duck DNS, encontre o campo para adicionar um novo domínio.
    2. Digite o nome desejado (ex.: debian13-lab).
    3. Clique em Add domain.
    4. O site irá detectar o IP público atual da sua conexão e associá-lo a esse domínio.

    A partir desse momento você já tem algo como:

    debian13-lab.duckdns.org

    Mas, por enquanto, o IP só é atualizado manualmente pelo site; o próximo passo é automatizar isso via Debian.

    Passo 2: preparar o Debian 13 (pacotes e usuário)¶

    Agora é hora de preparar o ambiente no Debian.

    2.1 Atualizar o sistema e instalar curl¶

    Abra um terminal no Debian 13 e rode:

    sudo apt update
sudo apt install curl

    O Duck DNS usa chamadas HTTPS simples para atualizar o IP, e a própria documentação oficial demonstra o uso de curl para isso.

    E o cron?

    Em instalações padrão do Debian, o cron costuma vir instalado por padrão. Para conferir se está rodando:

    2.2 Escolher onde guardar os arquivos do Duck DNS¶

    Há duas abordagens comuns:

    • Diretório no seu $HOME: mais simples para ambiente pessoal.
    • Diretório em /opt/duckdns com usuário dedicado: mais “profissional” e organizado.

    Para manter o tutorial simples e ainda assim organizado, será usado /opt/duckdns com um usuário de sistema.

    sudo useradd -r -d /opt/duckdns -s /usr/sbin/nologin duckdns
sudo mkdir -p /opt/duckdns
sudo chown duckdns:duckdns /opt/duckdns

    Por que um usuário dedicado?

    Um usuário de sistema dedicado reduz o impacto de um eventual problema de segurança no script, seguindo a boa prática de mínimo privilégio.

    Passo 3: criar o script de atualização do Duck DNS¶

    O coração da solução é um script que chama periodicamente a API de atualização do Duck DNS.

    3.1 Montar o script duck.sh¶

    Entre no diretório:

    cd /opt/duckdns
sudo -u duckdns nano duck.sh

    Cole o conteúdo abaixo (ajuste DOMINIOS e TOKEN):

    #!/bin/bash

DOMINIOS="debian13-lab"        # seu domínio ou lista separada por vírgula
TOKEN="SEU_TOKEN_AQUI"         # copie da página principal do Duck DNS
LOGFILE="/opt/duckdns/duck.log"

echo url="https://www.duckdns.org/update?domains=${DOMINIOS}&token=${TOKEN}&ip=" \
  | curl -k -o "${LOGFILE}" -K -

    A forma de chamada com echo url="..." | curl -k -o duck.log -K - segue exatamente o padrão mostrado na documentação oficial de instalação Linux com cron.

    Não exponha seu token

    O token do Duck DNS é uma credencial de API. Evite: - Subir esse arquivo em repositórios públicos. - Compartilhar prints onde o token aparece. - Deixar o arquivo com permissões muito abertas.

    3.2 Ajustar permissões¶

    Torne o script executável e mantenha as permissões restritas:

    sudo chown duckdns:duckdns /opt/duckdns/duck.sh
sudo chmod 700 /opt/duckdns/duck.sh

    Passo 4: testar o script manualmente¶

    Antes de automatizar, é fundamental testar manualmente.

    Execute:

    sudo -u duckdns /opt/duckdns/duck.sh

    Agora verifique o log:

    cat /opt/duckdns/duck.log

    Se tudo estiver certo, o arquivo deverá conter algo como OK, indicando que a atualização foi bem-sucedida, exatamente como descrito na documentação oficial.

    Testando a partir de outra máquina

    Em outra máquina na internet (por exemplo, uma VPS ou o 4G do celular em modo hotspot), teste:

    Passo 5: agendar atualizações com cron¶

    Agora que o script funciona, é hora de automatizar.

    5.1 Editar o crontab¶

    Edite o crontab do usuário duckdns:

    sudo crontab -u duckdns -e

    Adicione a linha:

    */5 * * * * /opt/duckdns/duck.sh >/dev/null 2>&1

    Essa linha agenda o script a cada 5 minutos, seguindo exatamente o exemplo de cron recomendado pelo próprio Duck DNS e por tutoriais consolidados.

    • */5 * * * * → a cada 5 minutos.
    • >/dev/null 2>&1 → descarta qualquer saída, mantendo tudo limpo.

    Por que 5 minutos?

    O intervalo de 5 minutos equilibra bem atualização rápida do IP com baixo consumo de recursos. Para ambientes críticos você pode reduzir, mas raramente é necessário.

    5.2 Verificar se o cron está rodando¶

    Use:

    ps -ef | grep cr[o]n

    Se o processo cron estiver ativo, o IP será enviado periodicamente para o Duck DNS, mantendo seu domínio sempre atualizado.

    Passo 6: alternativa moderna — usar systemd timers¶

    Em sistemas mais novos (como o Debian 13), é cada vez mais comum usar systemd timers no lugar do cron.

    A ideia é criar:

    • Uma unidade de serviço (duckdns.service) que roda o script.
    • Uma unidade de timer (duckdns.timer) que define o agendamento.

    6.1 Criar o serviço duckdns.service¶

    Crie o arquivo:

    sudo nano /etc/systemd/system/duckdns.service

    Conteúdo sugerido:

    [Unit]
Description=Atualizar DuckDNS (DNS dinâmico)

[Service]
Type=oneshot
User=duckdns
Group=duckdns
ExecStart=/opt/duckdns/duck.sh

    Essa abordagem é alinhada com exemplos de uso de systemd timers para serviços de DNS dinâmico, onde o serviço executa um script com curl para atualizar o IP.

    6.2 Criar o timer duckdns.timer¶

    Crie o arquivo:

    sudo nano /etc/systemd/system/duckdns.timer

    Conteúdo:

    [Unit]
Description=Timer para atualização DuckDNS (a cada 5 minutos)

[Timer]
OnCalendar=*:0/5
Persistent=true

[Install]
WantedBy=timers.target
    • OnCalendar=*:0/5 → executa a cada 5 minutos.
    • Persistent=true → se o sistema ficou desligado, o systemd tenta compensar a próxima execução.[^3]

    Entendendo o OnCalendar

    Você pode usar expressões mais “humanas”, como OnCalendar=hourly ou OnCalendar=*-*-* *:0/10 (a cada 10 minutos). Consulte man systemd.timer para mais exemplos.

    6.3 Ativar o timer¶

    Execute:

    sudo systemctl daemon-reload
sudo systemctl enable --now duckdns.timer

    Verifique:

    systemctl list-timers | grep duckdns

    Você deve ver o duckdns.timer listado, com a última e próxima execução agendadas, comportamento idêntico aos exemplos de timers para serviços de DNS dinâmico.

    Passo 7: validando a configuração na vida real¶

    Com cron ou systemd timer configurados, é hora de testar como se estivesse em uso real.

    1. Anote o IP atual que o Duck DNS mostra na página principal.
    2. Force uma mudança de IP:
      • Reiniciando o roteador.
      • Ligando/desligando o link (em alguns provedores).
    3. Aguarde alguns minutos (de acordo com o intervalo configurado).
    4. Acesse novamente a página do Duck DNS e verifique se o IP foi atualizado.

    Testando com SSH

    No seu cliente:

    ssh usuario@debian13-lab.duckdns.org

    Se o roteador estiver com o port forwarding configurado para a porta 22, você deve conseguir acessar seu servidor normalmente.

    Se algo não funcionar:

- Veja o status do serviço/timer (se estiver usando systemd):

    sudo systemctl status duckdns.service
sudo systemctl status duckdns.timer

    Exemplos práticos de uso do Duck DNS¶

    Uma vez que você tem um domínio Duck DNS atualizado automaticamente, pode usá-lo em vários cenários.

    Acesso SSH remoto ao servidor Debian¶

    • Configure o roteador para encaminhar a porta 22 (ou outra) para o IP interno do seu Debian.
    • Use sempre o hostname Duck DNS no cliente SSH:
    ssh rodrigo@debian13-lab.duckdns.org

    Nunca exponha SSH sem proteção

    • Use chaves SSH em vez de senha.
    • Considere mudar a porta padrão.
    • Utilize fail2ban ou firewall para limitar tentativas.

    Servidor web/Nextcloud acessível pela internet¶

    • Configure um servidor web (Nginx, Apache) no Debian.
    • Aponte o virtual host para o hostname Duck DNS.
    • Faça port forwarding da porta 80/443 no roteador.
    • Opcionalmente, use um proxy reverso com TLS.

    Duck DNS pode ser usado como base de um ambiente “homelab” acessível de qualquer lugar, seguindo boas práticas de DNS dinâmico e automação de IP.

    Boas práticas de segurança e manutenção¶

    Ter um hostname acessível pela internet é poderoso, mas exige cuidado.

    • Proteja seus serviços:
      • SSH com chave.
      • Aplicativos web com autenticação e HTTPS.
    • Monitore o log do Duck DNS:
      • De tempos em tempos, confira /opt/duckdns/duck.log para garantir que as atualizações estão OK.[^2]
    • Mantenha o sistema atualizado:
      • Use sudo apt update && sudo apt upgrade regularmente.

    Multi-domínios com Duck DNS

    A API do Duck DNS aceita uma lista de domínios separados por vírgula (sem espaços), atualizando todos com o mesmo IP numa única chamada. Exemplo no script:

    DOMINIOS="casa-lab,debian13-lab,media-server"

    Próximos passos recomendados¶

    Agora que o Duck DNS está funcionando no Debian 13, alguns próximos passos interessantes:

    • Integrar com um servidor VPN (WireGuard, OpenVPN) usando o hostname Duck DNS.
    • Automatizar backups remotos usando rsync ou restic apontando para o hostname.
    • Monitorar disponibilidade do servidor usando ferramentas externas que testam debian13-lab.duckdns.org.

    Com um simples script e um agendador (cron ou systemd timer), você aplica na prática um padrão de infraestrutura usado há anos por administradores de sistemas, apoiado em documentação oficial e boas práticas de DNS dinâmico.
