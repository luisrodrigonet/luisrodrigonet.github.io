    Como usar IP dinâmico e fixar IP estático no Debian Linux

    Por que o IP da sua máquina muda¶

    Imagine que você instala um servidor Debian em casa ou na empresa, configura SSH, coloca um serviço web no ar e compartilha o endereço com o time. No dia seguinte, ninguém consegue mais acessar: o IP mudou “do nada”.

    Essa mudança acontece porque, por padrão, o Debian normalmente recebe um endereço de rede de forma dinâmica, via DHCP, sempre que sobe a interface de rede. Isso é ótimo para estações de trabalho, mas pode se tornar um pesadelo em servidores, firewalls e equipamentos que precisam ser encontrados sempre no mesmo endereço.

    Neste guia, o objetivo é simples: mostrar, passo a passo, como usar um endereço de rede fornecido dinamicamente e, quando for necessário, como fixar um IP estático na interface de rede do Debian Linux, usando métodos clássicos e modernos.

    Ao final do artigo, você terá um passo a passo claro para:

    • Manter IP dinâmico quando fizer sentido.
    • Fixar um IP estático no Debian usando /etc/network/interfaces.
    • Configurar IP estático e dinâmico via nmcli (NetworkManager), comum no Debian desktop.
    • Validar se tudo está realmente funcionando.

    Conceitos rápidos: IP dinâmico vs IP estático¶

    Antes de colocar a mão na massa, é importante alinhar o vocabulário.

    • IP dinâmico (via DHCP): o roteador/servidor DHCP entrega automaticamente um IP para a máquina, por um tempo limitado (lease). É o padrão na maioria das instalações do Debian.

    • IP estático: o endereço é configurado manualmente na máquina e não muda enquanto a configuração permanecer a mesma. Ideal para:

      • Servidores web, banco de dados, arquivos.
      • Máquinas que recebem redirecionamento de portas (NAT).
      • Equipamentos que precisam de regras fixas de firewall.

    Regra de ouro

    Use IP dinâmico para desktops e notebooks comuns. Use IP estático para servidores, impressoras de rede, equipamentos críticos e qualquer serviço que precise ser encontrado sempre no mesmo lugar.

    Pré‑requisitos e visão geral do que será feito¶

    Nesta seção você verá o panorama geral do processo, para saber exatamente o que vai fazer nas próximas etapas.

    Você vai precisar de:

    • Um Debian 11 ou 12 (mas as ideias valem para versões anteriores).
    • Acesso ao terminal com privilégios de root ou sudo.
    • Acesso físico ou remoto (SSH) à máquina que será configurada.

    O passo a passo será:

    1. Descobrir o nome da interface de rede que será configurada.
    2. Ver como deixar essa interface em modo dinâmico (DHCP).
    3. Ver como fixar um IP estático pelo arquivo /etc/network/interfaces.
    4. Aprender a fazer o mesmo via NetworkManager (nmcli).
    5. Validar as configurações com comandos de teste.

    Passo 1: identificar a interface de rede¶

    Primeiro, descubra qual interface deseja configurar (ex.: eth0, enp0s3, ens18).

    No terminal:

    ip link

    ou

    ip addr

    Esses comandos listam todas as interfaces disponíveis, indicando nomes como enp2s0f0 ou ens18 para conexões cabeadas.

    2: enp2s0f0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc mq state UP group default qlen 1000
    link/ether 3c:07:54:05:a3:89 brd ff:ff:ff:ff:ff:ff
    altname enx3c075405a389
    inet 192.168.1.134/24 brd 192.168.1.255 scope global dynamic noprefixroute enp2s0f0
       valid_lft 3276sec preferred_lft 3276sec
    inet6 2804:13c:201:e100:beb1:d497:eec9:bec7/64 scope global temporary dynamic
       valid_lft 6812sec preferred_lft 6812sec
    inet6 2804:13c:201:e100:3e07:54ff:fe05:a389/64 scope global dynamic mngtmpaddr noprefixroute
       valid_lft 6812sec preferred_lft 6812sec
    inet6 fe80::3e07:54ff:fe05:a389/64 scope link noprefixroute
       valid_lft forever preferred_lft forever

    Interfaces mais comuns

    • enp0s3, ens18, enp2s0f0: interfaces Ethernet em máquinas virtuais ou físicas modernas.
    • eth0: nome clássico em versões mais antigas.

    Anote o nome da interface que tem estado UP e endereço IP associado.

    Passo 2: usando IP dinâmico (DHCP) no Debian via /etc/network/interfaces¶

    Nesta seção você verá como garantir que o Debian receba IP automaticamente via DHCP, de forma persistente.

    O Debian ainda utiliza, em muitos cenários, o arquivo /etc/network/interfaces para descrever como as interfaces devem ser ativadas. Um exemplo simples de configuração para receber IP via DHCP é:

    auto enp0s3
allow-hotplug enp0s3
iface enp0s3 inet dhcp

    Nesse trecho:

    • auto enp0s3 indica que a interface deve ser levantada automaticamente na inicialização.[9][7]
    • allow-hotplug enp0s3 permite que ela seja ativada quando o cabo é conectado.
    • iface enp0s3 inet dhcp diz ao Debian para obter as configurações IPv4 via DHCP.[2][7]

    Para editar o arquivo:

    sudo nano /etc/network/interfaces

    Ajuste para algo próximo ao exemplo acima, salvando ao final.[8][9]

    Para aplicar a configuração:

    sudo systemctl restart networking

    ou, em versões que ainda utilizam ifupdown diretamente:

    sudo ifdown enp0s3 && sudo ifup enp0s3

    Esses comandos reiniciam a interface e fazem com que ela solicite um novo IP ao servidor DHCP.

    Exemplo completo de arquivo

    source /etc/network/interfaces.d/*

auto lo
iface lo inet loopback

allow-hotplug enp0s3
iface enp0s3 inet dhcp
    Esse é um modelo comum em servidores simples com apenas uma interface configurada por DHCP.

    Passo 3: usando IP dinâmico com NetworkManager (nmcli)¶

    Em desktops Debian mais recentes, o NetworkManager costuma gerenciar a rede por padrão. Isso significa que a interface é controlada por conexões lógicas (profiles) e você pode alternar entre DHCP e IP fixo facilmente.

    Primeiro, liste as conexões conhecidas:

    nmcli connection show
    NAME                UUID                                  TYPE      DEVICE
Wired connection 1  aba7be69-887f-4321-a552-f5409b5aded9  ethernet  enp2s0f0
sem_nome_5g         2ad5b529-e662-4a3a-bbbd-3b1762c2d6df  wifi      wlp3s0

    Depois, para definir que a conexão use IPv4 automático (DHCP):

    nmcli connection modify "MINHA-CONEXAO" ipv4.method auto
nmcli connection up "MINHA-CONEXAO"

    Nesses comandos:

    • "MINHA-CONEXAO" é o nome exibido na coluna NAME do nmcli connection show.
    • ipv4.method auto indica que o IP será obtido via DHCP.

    Interface gráfica em modo texto

    Se preferir um assistente em modo texto, use:

    sudo nmtui

    O nmtui permite editar a conexão, selecionar Automatic (DHCP) em IPv4 e salvar as alterações sem lembrar todos os comandos de cabeça.

    Passo 4: quando e por que fixar um IP estático¶

    Nesta seção você vai entender em que cenários o IP estático é obrigatório e o que precisa planejar antes de configurá‑lo.

    Use IP estático quando:

    • For expor serviços (HTTP, SSH, banco de dados) na rede local ou para a internet.
    • For criar regras de firewall específicas por IP.
    • For apontar o DNS interno (ou do roteador) para o seu servidor.

    Antes de configurar:

    • Decida qual IP usar, certificando‑se de que ele não está dentro do pool DHCP do roteador, para evitar conflitos.
    • Tenha em mãos:
      • IP que será fixado (ex.: 192.168.1.100).
      • Máscara (ex.: 255.255.255.0).
      • Gateway (ex.: 192.168.1.254).
      • Servidores DNS (ex.: 8.8.8.8 e 8.8.4.4).

    Cuidado com IP duplicado

    Se você escolher um IP que o servidor DHCP também possa entregar, corre o risco de ter dois hosts com o mesmo IP, causando quedas intermitentes e problemas difíceis de diagnosticar.

    Passo 5: fixando IP estático no Debian via /etc/network/interfaces¶

    Aqui você verá o passo a passo clássico e robusto para servidores: configurar IP estático editando o arquivo /etc/network/interfaces.

    Abra o arquivo de configuração:

    sudo nano /etc/network/interfaces

    Crie ou ajuste o bloco da interface desejada, por exemplo:

    auto enp2s0f0
allow-hotplug enp2s0f0

iface enp2s0f0 inet static
    address 192.168.1.100
    netmask 255.255.255.0
    gateway 192.168.1.254
    dns-nameservers 8.8.8.8 8.8.4.4

    Esse modelo segue o padrão recomendado para Debian 11 e 12 quando se usa ifupdown.

    • address define o IP fixo da interface.
    • netmask determina o tamanho da rede.
    • gateway é o roteador padrão.
    • dns-nameservers define os servidores DNS que serão escritos em /run/systemd/resolve ou em resolvers equivalentes, conforme a configuração do sistema.

    Salve o arquivo e feche o editor. Em seguida, aplique as configurações:

    sudo systemctl restart networking

    ou:

    sudo ifdown enp2s0f0 && sudo ifup enp2s0f0

    Esses comandos derrubam e sobem a interface com as novas configurações estáticas.

    Exemplo em versões mais antigas

    Em versões como o Debian 7, o processo é semelhante, apenas mudando o nome da interface (por exemplo, eth0). 

    auto eth0     
iface eth0 inet static         
address 192.168.0.10         
netmask 255.255.255.0         
gateway 192.168.0.1

    Passo 6: fixando IP estático usando NetworkManager (nmcli)¶

    Nesta seção você verá como fixar um IP em máquinas que usam NetworkManager, sem editar arquivos manualmente.

    1. Liste as conexões:
    nmcli connection show
    1. Suponha que a conexão se chame "Wired connection 1". Para definir um IP estático:
    sudo nmcli connection modify "Wired connection 1" ipv4.addresses 192.168.1.250/24
sudo nmcli connection modify "Wired connection 1" ipv4.gateway 192.168.1.254
sudo nmcli connection modify "Wired connection 1" ipv4.dns "8.8.8.8,8.8.4.4"
sudo nmcli connection modify "Wired connection 1" ipv4.method manual
sudo nmcli connection up "Wired connection 1"

    Esses comandos definem endereço, gateway, DNS e mudam o método de IPv4 para manual, ativando em seguida a conexão.

    Usando interface gráfica do GNOME

    No Debian Desktop, você pode fazer o mesmo em Configurações → Rede → Wired: alterar o método IPv4 para Manual, informar IP, máscara, gateway e DNS, e salvar.

    Passo 7: alternando entre IP dinâmico e estático rapidamente¶

    Às vezes você precisa testar um cenário com IP estático e, depois, voltar ao DHCP. Nesta seção você verá como alternar entre esses modos sem mistério.

    Pelo arquivo /etc/network/interfaces, a ideia é simples:

    • De estático:
    iface enp0s3 inet static
    address 192.168.1.100
    netmask 255.255.255.0
    gateway 192.168.1.1
    • Para dinâmico:
    iface enp0s3 inet dhcp

    Basta ajustar o bloco da interface e reiniciar a rede com systemctl restart networking ou ifdown/ifup.

    Com NetworkManager, o caminho é:

    • Para mudar de estático para DHCP:
    nmcli connection modify "MINHA-CONEXAO" ipv4.method auto
nmcli connection up "MINHA-CONEXAO"
    • Para ir de DHCP para estático, use o conjunto de comandos mostrado na seção anterior (ipv4.addresses, ipv4.gateway, ipv4.dns, ipv4.method manual).

    Use perfis diferentes

    Uma boa prática é criar duas conexões diferentes no NetworkManager: uma chamada srv-dhcp e outra srv-static, por exemplo. Assim, você alterna entre perfis sem editar nada, apenas ativando a conexão desejada.

    Atenção ao acesso remoto

    Se você estiver conectado via SSH e mudar o IP da interface em uso, a sessão pode cair. Sempre tenha um plano de acesso alternativo (console, IPMI, KVM, etc.) antes de aplicar mudanças em servidores de produção.

    Passo 9: alternativa avançada — IP “fixo” via reserva DHCP¶

    Por fim, vale mencionar uma solução híbrida: manter o cliente usando DHCP, mas o roteador sempre entregar o mesmo IP para aquele MAC address.

    Num servidor DHCP (como o isc-dhcp-server), é possível definir reservas com base no endereço MAC, fazendo com que a máquina receba sempre o mesmo IP, embora continue em modo DHCP. Isso é útil quando você prefere centralizar o controle de endereços no roteador/servidor de DHCP, sem editar todos os clientes.

    Quando usar reservas DHCP

    Use reservas DHCP quando: - Você administra a rede a partir de um único servidor DHCP. - Quer evitar que usuários alterem manualmente IPs nos hosts. - Precisa de IPs previsíveis, mas com gestão centralizada.

    Com esse passo a passo, você domina tanto o uso de endereços dinâmicos quanto a configuração de endereços estáticos na interface de rede do Debian Linux, usando métodos tradicionais (/etc/network/interfaces) e modernos (nmcli/NetworkManager), sempre com foco em estabilidade, previsibilidade e boa prática de administração de sistemas.
